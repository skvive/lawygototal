## 1. 목적
LAWYGO JOURNAL / WIKI / PAN / NOTE / PRO를 하나의 글로벌 상단 메뉴로 연결하고, 각 서비스의 독자적인 편집 경험은 유지한다. 실제 운영 기능과 아직 개발 중인 소개/베타 기능을 명확히 구분한다.

## 2. 현재 코드 조사 결과
- `static/brand-shell.js`, `static/site-nav.js`, `static/journal.html`, `static/pan.html`의 헤더가 분리돼 있어 서비스 전환 UI가 통일되지 않았다.
- `static/pan-platform.js`, `pan_public_feed.py`, `app.py`에 Blogger/YouTube RSS 수집, PAN 콘텐츠 API, 블로그/영상/쇼츠 영역은 **이미 존재**한다. 채널 등록·수집 갱신·검수·분류 신뢰도·프로필 상세는 고도화 대상이다.
- `static/note.html`은 노트 소개·CMS 피드 중심. 별도 권한 보호된 AI 워크스페이스 연결이 필요하다.
- `static/wiki-page.js` + `/api/wiki/search`는 공개 승인 글을 표시한다. 법률백과 원본 자료와 비공개 문서를 구분한 출판 파이프라인이 필요하다.
- `static/pro.html`은 송무 OS 기능의 베타 안내 중심이다. 실제 업무 로그인 진입을 구분한다.
- 기존 상세 QA: `docs/release/LAWYGO_DETAIL_DESIGN_QA_20261102.md`. 이번 작업에는 새 브라우저 검수 필요.

## 4. PAN
1. 관리자 승인 채널/변호사 프로필 등록(YouTube channel ID, Blogger site, 분야, 지역, 공개/비활성).
2. RSS/공식 API 우선으로 최신글만 증분 수집, 중복 제거, 재시도, 오류 관제. 제한 우회·무단 본문 재발행 금지.
3. 유튜브 롱폼/Shorts 오분류 방지(메타 검증), 썸네일·제목·출처·날짜·원문 링크, 블로그 별도 탭.
4. 변호사 상세/상담 CTA를 실제 권한·상담 여정에 연결. 광고 노출 명확한 표기.
5. URL 안전검증, DOM XSS, 콘텐츠 삭제 요청, 통계 이벤트 정확성 점검.

## 5. NOTE
- 로그인 후: 문서 업로드/OCR → 소스별 법률 AI 질의 → 판례/법령 검토 → 서면 초안 → 결과 저장/내보내기.
- **보안 원칙:** 비공개 운영 AI 소스와 데이터는 이 저장소에 직접 반입하지 않는다. 인증된 원본 서비스의 BFF/SSO 연동을 우선 검토하며 프로젝트·테넌트·파일 접근권한·감사 로그를 별도 검증한다.
- 의뢰인 정보, 비공개 노트, AI 학습 데이터의 공개 피드 노출을 금지한다.
