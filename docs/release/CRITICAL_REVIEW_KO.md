# LAWYGO v3 비판적 검수 · 개선 사항

## 실제 수정 사항

| 발견·개선 대상 | 적용한 수정 |
|---|---|
| 기존 CMS는 콘텐츠 등록은 가능하지만 광고 캠페인 노출 순서와 광고주 측정 기능이 없음 | `growth_v3.py` 캠페인 관리, 유료 노출 구분 피드, 이벤트 집계, 관리자 화면 추가 |
| 게시판 목록의 드래그앤드롭 서버 저장이 없음 | 테넌트 범위 검사 후 원자적 순서 변경, 마우스 DnD와 키보드용 버튼 구현 |
| 변호사 자격 검증 수동 절차가 인터페이스에 없음 | 신청·관리자 승인·반려 및 감사 기록 API, 심사 화면 구현 |
| 구독 권한 이벤트가 중복 적용될 우려 | HMAC 인증·5분 재전송 제한·이벤트 ID 중복 방지, 최소 회원 기준 접근 제어 |
| 이메일 뉴스레터 수신동의·확인·수신거부 기능 부재 | TLS SMTP 기반 발송 설정, 이중 확인, 무료 수신거부, 발송 건수 제한 |
| 서비스 메인에 구독 및 유료·일반 콘텐츠 분리 안내 부족 | 실데이터 API 기반 피드와 월 2회 무료 구독 입력 폼 추가 |
| 모바일 화면에서 광고 관리 콘텐츠가 길게 배치됨 | 2열 KPI, 적응형 액션 버튼, 화면 겹침 개선, 모바일 사이드바를 고정형 드로어로 조정 |
| SEO 대표 비주얼/아이콘 보강 필요 | 실제 한글 폰트로 조판한 1200×630 OG 이미지와 L 심벌 favicon 추가 |
| AI 홍보용 합성 이미지의 작은 글씨는 깨질 수 있음 | 운영 화면은 글자 없는 사진 자산만 사용하고 정확한 한글을 DOM 텍스트로 별도 렌더링 |
| 최초 사이트 문구 일부 `법률 경제` 등의 띄어쓰기 모호 | `법률·경제` 등 표기 통일, 공개 안내 문구 보강 |

## 잔여 출시 위험

- 법률 AI의 인용 정확도, 해당 시점 판례·법령 최신성, 개인정보 처리 적법성은 **API 단위 검증으로 보장되지 않습니다**. 변호사 승인 워크플로가 필요합니다.
- 운영 DB와 독립 SQLite 간 정합성 및 법무법인 테넌트 분리, 장기 운영 백업 검증은 staging 실계정 테스트가 필요합니다.
- Google OAuth, Blogger·YouTube 자동 동기화는 모의 테스트를 통과했으나 Google Cloud 동의 화면/할당량 설정으로 실계정 연결이 실패할 수 있습니다.
- Stripe Checkout은 기존 `lexid` PR 별도 검토 중입니다. 신규 서버 간 HMAC 이벤트는 **Stripe 원본 웹훅이 아니며**, 운영 결제 서버가 서명·포워딩해야 합니다.
- 익명 이벤트는 브라우저 쿠키 중복을 줄인 임시 수치로, 신뢰할 수 있는 광고 과금 측정·사기 탐지는 별도 구축이 필요합니다.
- 뉴스레터 운영은 SPF/DKIM/DMARC, 사전 동의, 수신거부, 보존기간/발송거부 로그, 광고성 정보 법규 점검 후 활성화해야 합니다.
- 실제 고객 계약·결제·광고 고지, 법률 자격 광고 규정은 추가 법무검토 필요.

## 테스트 구분

1. 38개 기존 회귀 테스트 + 11개 성장 기능 테스트 + 4개 뉴스레터 테스트 = **53개** 통과.
2. 실제 네트워크 HTTP 서버 15단계 E2E 테스트: 로그인/게시판/게시글 CRUD/광고/이벤트/순서/메일 차단/삭제·복원/로그아웃 모두 통과.
3. 정적 HTML·CSS·JS 브라우저 렌더링: 홈, 채널, 위키, 판, 노트, 마케팅 대시보드 PC·모바일 12화면. JS 페이지 오류 0, 가로 넘침 0, 드래그 순서 클라이언트 UI 2환경 성공.
4. localhost 브라우저 접속은 정책 차단으로 직접 실행되지 않아 실제 브라우저↔API 연동은 **검증하지 못함**. 브라우저의 DOM 렌더와 서버 HTTP 테스트는 별개로 명시.
5. 운영 Google·Gemini·Stripe·SMTP 및 LAWYGO Supabase/Neon은 실계정 검증 전입니다.
