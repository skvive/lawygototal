## 발견·개선 사항
1. 기본 게시판 개수 계산 12 → 13으로 교정.
2. async 파일 업로드 SQLite 스레드 예외를 요청별 연결 설정으로 해결.
3. 관리자·편집자 목록에서도 타인 비공개 노트가 노출되지 않도록 제한.
4. 미승인 글 노출, 일반회원의 승인 우회, 중복 수정 충돌 방지.
5. 비밀 첨부파일의 타인 접근 차단, 파일 유형 시그니처 검사.
6. 판의 상담문의함을 프로필 작성자만 열람할 수 있게 제한.
7. 관리자 휴지통/복원 및 노트 원문 발췌, 상담 문의함 화면 추가.

## 운영 전 필수 작업
- LAWYGO PR #37은 미병합 초안. GitHub 브랜치의 빌드·타입 검사/원본 Supabase DB/Google OAuth E2E는 수행하지 않았습니다.
- 새 독립 CMS는 별도 SQLite DB이며, LAWYGO 운영 데이터와 양방향 동기화된 상태가 아닙니다.
- 자동 Blogger·YouTube 수집, 이메일 전송·안심전화, Stripe, 판례 API·실제 생성형 AI 분석은 추가 연동이 필요합니다.
- 프로덕션 HTTPS + Secure Cookie + rate limit + CSP + 악성코드 검사 + 비밀 데이터 암호화 + 권한관리 + 백업/마이그레이션 + 법률 콘텐츠 검증이 필요합니다.
- 관리된 Chromium은 localhost·file URL 접근을 보안정책으로 차단했으므로 풀 브라우저 기능 E2E는 수행하지 못했습니다. API 검증은 실제 HTTP 서버에서 수행했습니다.
